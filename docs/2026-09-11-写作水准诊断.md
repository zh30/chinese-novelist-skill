# 写作水准诊断：v3.1 真正卡住的地方

> 立场：职业写作者读 skill，不是产品经理读流程。
> 对象：当前仓库 `main`（v3.1.0，`3f1f9fa`）。
> 目的：指出哪些问题在伤害中文小说本身，以及哪几处若做大规模改变，才会真正抬升写作水准。
> 执行方案：[plans/2026-09-11-写作水准优化执行方案.md](plans/2026-09-11-写作水准优化执行方案.md)

---

## 0. 判断

这个 skill 已经知道好小说长什么样。它还不能让模型写出好小说。

v3.0 的创作原则——独特性、必然性、复杂性、余震，人物压力系统，因果脊柱，分层修订，伟大作品门控——在观念上已经够用，部分段落甚至高于多数写作课。v3.1 把这些原则装进了可恢复的工厂：有界冷启动、章节事务验收、批量生产、跨书同质报警。工厂很能干。它奖励的是**完整的小说状物体**，不是**只能由这些人物、用这种中文写成的作品**。

写作水准上不去，不是因为还缺一张清单。是因为模型实际优化的，是最后被测量、且最容易做完的那一层。

当前被测量的是：

- 正文是否存在，是否满 3000 字
- `review.md` 三个字段是否非空
- 仪表盘滚动摘要是否出现本章字样
- 关键词层面的 AI 痕迹是否超阈值

这些都能在同一轮里被填绿。读者是否被具体的人逼进具体的处境，没有进入验收。

## 1. 已经做对、不要退回去的事

后面的批评默认这些成果保留。

1. **先发现后规划，先分岔后收敛。** `creative-compass.md` 禁止把“修仙/重生/悬疑”直接塞进题材模板，要求三个方向改变代价、对手价值、冲突尺度。这是正确的创作者纪律。
2. **人物是压力机器，不是性格词。** 公开追求、隐秘饥饿、保护策略、自我谎言、对手作为另一种活法——这些字段若被真正写进场面，人物就会活。
3. **主题保持为问题。** 禁止“爱能战胜一切”式答案。这挡住了最常见的伪深刻。
4. **写作与审稿分离、脚本只是烟雾报警器、拒绝伪完成。** 原则写对了。
5. **干净正文与工作台分家。** `manuscript/zh/` 作为唯一事实来源，是正确的出版意识。
6. **不强制章章反转、不打可互相抵消的总分。** 从钩子教条和百分比关系里走出来，是一次真实进步。

问题不在这些句子。问题在：它们几乎从不进入生成句子的那一毫秒。

## 2. 核心裂缝：原则写给作家，流程写给工厂

v3.0 说：伟大不能由清单保证。  
v3.1 说：一章的完成条件是事务验收通过。

自动驾驶连续两次验收失败就停机。停机保护的是文件完整性，不是文学。模型很快学会：把任务卡、场景因果、复盘、仪表盘写成看起来很狠的短句，正文用解释、转述和达标字数填满。复盘里的“最弱一处”常常是一句正确空话，因为写它的，就是刚写完正文的同一个上下文。

有界冷启动把续写输入收成：

- 仪表盘（含每章不超过 40 字的一行摘要）
- 创作宪章
- POV 人物卡
- 上一章末尾 800 字

并**禁止默认重读最近 1–3 章全文**。

这对 token 是理性的。对中文长篇是敌意的。小说的声音、意象污染、人物口吻的微小偏移、上一场没说完的半句话，都活在那被禁止重读的几千字里。40 字摘要只能保存情节，不能保存文风。800 字只能保存余韵的尾巴，不能保存这本书自己的句法。

于是出现一种稳定的失败形态：

> 大纲像能写好的书。章节像用大纲 viscose 出来的说明书。每章单独看“结构完整”，十章连起来没有同一个人在呼吸。

批量生产把这种失败放大。跨书 4-gram 能抓住人名和开篇撞车，抓不住同一套保护策略、同一套“因为所以但”、同一套冷静克制腔在不同皮囊下复读。

**一句话：当前架构让“写完”比“写对”便宜，让“像小说”比“是小说”便宜。**

## 3. 具体病灶

### 3.1 同轮自审是空转

`SKILL.md` 要求写完正文后按 `editorial-revision.md` 做独立编辑，并“做一处有胆量的修改”。`editorial-revision.md` 的第 0 轮是体验通读：只做 `+ / ? / X / ~ / !` 边注，不编辑。

同一轮、同一上下文、刚写完的模型，做不到这件事。它看见的是自己的意图，不是读者的经验。它会：

- 把刚写的解释腔标成“必要压缩”
- 把最漂亮的一段标成 `!`
- 删一个形容词，当作勇敢一刀
- 在复盘里填写“最弱处：某段略平”，然后交付

伟大作品门控同样由写作者自己打证据。没有看不见大纲的人来读。没有只拿 `manuscript/zh/`、禁止打开工作台的通道。

职业编辑的价值几乎全在**信息不对称**：他不知道你想表达什么，只知道自己读到了什么。这个 skill 把编辑协议写得很专业，却把信息不对称拆掉了。

### 3.2 人物档案很强，进入正文的通道很窄

`character-template-v2.md` 里有两处真正能抬升文字的字段：

- **首先会注意的细节**：价格、秩序、面孔、出口、气味、工具、声音
- **声音样本**：三句不同权力关系中的对白

这是作家用的东西。冷启动却只要求“本章 POV 人物卡”，不要求把这三句样本当作本章句法的硬约束，也不要求开场第一段必须由“此人此刻会先看见什么”写成。

结果是：档案里写着“她先看价格和出口”，正文里所有人先看眼神和气氛。档案里有三句有身份的话，章里所有人说完整、正确、漂亮的书面语。

角色沙盘本应补上这一层。它现在的输出合同是：

> 行动倾向、场景建议、一句可能说出口的话。

“一句对白”是最差的合同。它生产口号，不生产现场。人物活在**注意、误判、不肯说出口的那半句、身体如何保护自己**里，不活在一句可被导演抄进任务卡的台词里。

更糟的是内部打架：

| 文件 | 沙盘何时跑 | 读什么 |
|------|------------|--------|
| `SKILL.md` | 人物不自然或多人冲突时才跑 | 有界冷启动，禁止默认重读近章 |
| `14-角色沙盘模式.md` | “不是每章必须的仪式” | 导演仍读大纲、人物档案、**最近 1–3 章** |
| 单角色运行时文件 | — | 仍有信任度 / 依赖度 / 冲突度百分比，以及压力 `__/10` |

模型会走最便宜的路：把章节判成“普通章”，跳过沙盘。v3 把沙盘从每章必跑改成高价值工具，方向对；但没有替代物去强制**感知与信息边界**进入每一段正文。任务卡上的“不愿面对 / 说出的事”被填成抽象名词，就过关了。

### 3.3 场景会写因果，不会写现场

`scene-plan.md` 要求：

> 因为 ___，所以 ___；但 ___。

这对结构有用。单独使用，它会把每一场写成功能机。职业写作者在进场前还要决定另一组事，这个 skill 几乎不问：

- 这场谁知道什么、读者站在谁的知情位置
- 开场第一眼是什么物件或声音，为什么是这个人会看见它
- 这场的时间是被压缩、被拉长，还是几乎实时
- 最强的一拍放在对白、动作、沉默还是离场
- 这场结束后，哪句话或哪个动作不准再解释

缺少这些，正文就用转述推进因果：“他意识到对方在隐瞒”“气氛变得紧张”“她的心情很复杂”。因果链在工作台里是绿的，场面在稿纸上不存在。

`dialogue-writing.md` 仍把“传递信息”列为合法对白任务，例句是说明腔（“我找到凶器了，在河边草丛里。”）。这和人物模板“对白是一场交易”互相拆台。旧手艺没有清干净。

### 3.4 字数是正在生效的美学

标准长篇 ≥3000 字，快速 ≥2500，短篇 ≥6000。事务验收把字数做成硬失败。

中文网文有字数习惯，可以理解。作为质量函数，它在训练模型**注水**：把一个已经完成价值变化的场面，用心理活动、走位、回忆和天气写到 3000。短篇 6000 字红线同样在邀请中段重复确认已知信息。

`quality-checklist.md` 写了“字数只是边界，不是质量代理”。脚本不读这句话。自动驾驶读脚本。

真正该问的是：这场的压力变化完成了没有。完成了就该停。没完成，写到 8000 也是空的。

### 3.5 中文被检测，没有被生成

`style-polishing.md` 对文风的判断是对的：风格是一颗具体心智选择看什么、略过什么、怎样排列经验。`check_ai_style.py` 检测的是另一件事：空泛形容词、四字成语表、然而/因为/所以、突然/忽然、情绪标签句。

检测有用，像验血。它不能造血。而且会误伤：中文叙事需要“然而”和“因为”；有些四字词在特定人物嘴里是声音，不是 AI 味。阈值一到，修订轮开始替换同义词，声音更假。

中文小说真正致命的生成病，关键词表抓不准：

1. **解释在场面之后再讲一遍。**
2. **所有人的对白都像受过完整中文写作训练。**
3. **情绪先有结论，再找身体动作配图（握拳、胸口一紧、低下头）。**
4. **句长均匀，段长均匀，每段都把话说完。**
5. **意象正确但无污染**：钥匙始终是钥匙，不会在中段变成控制。
6. **书面语叙述 + 书面语对白**，没有口头的残句、错序、脏词、职业词库。

这些要在**生成时**用本书的样本和禁止句压住，不能靠写完后扫词。

### 3.6 参考层是两代手艺叠在一起

`references/` 里大约 40 个文件。v3 核心其实只有少数几个真正在干活：

- `creative-compass.md`
- `character-template-v2.md`
- `chapter-workspace-template.md`
- `editorial-revision.md`
- `quality-checklist.md`
- `style-polishing.md`
- `14-角色沙盘模式.md`（部分）

大量 v1/v2 沉积仍可被“按问题加载”叫起来，并且彼此打架：

| 沉积 | 和 v3 的冲突 |
|------|----------------|
| `13-钩子映射表.md`、`hook-techniques.md` | v3 明确不强制章章反转 |
| `07-叙事节奏曲线.md`、`11-叙事节奏框架.md`、`05-节奏健康报告.md` | 三套节奏语言并存 |
| `06-出版门控.md` | 和“伟大作品门控 / 证据而非分数”叠床 |
| `dialogue-writing.md` 的信息型对白 | 和“对白是交易”叠床 |
| `content-expansion.md` | 在字数红线旁边，等于鼓励注水 |
| 沙盘文件里的百分比和 1–3 章重读 | 和有界冷启动、禁止百分比叠床 |
| `WORKFLOW_GUIDE.md`、`OPTIMIZATION_PLAN.md` | 仍是三阶段 + 红绿灯 + 极简 10 字段，与 v3.1 不符 |

模型在上下文拥挤时会抓最像“规则表”的旧文件。沉积不是中性的档案，它会把文风往回拉。

测试也在锁口号，不锁文章。`tests/test_skill_docs.py` 断言 `SKILL.md` 里出现“独特性”“伟大作品门控”“有界冷启动”等词，并限制行数。这保证入口像 v3，不保证任何一章写得像小说。仓库里没有金标章节，没有“这段是过关中文 / 这段是合格空壳”的对照。

### 3.7 没有读者，没有本书自己的耳朵

职业写作者靠两样东西校准手：

1. **重读自己已经写好的、真正有生命的段落**，让新手感跟着旧手感走。
2. **把稿给一个不知道大纲的人**，听他在哪一页不想翻。

这个 skill 两样都没有。每章像从模板零起步。跨书相似度看的是别人的书，不看自己前二十章把哪几种比喻写死了。卷审计每 10 章才做一次，而且由同一个写作上下文填写因果和人物弧线——又是自审。

## 4. 大规模改变才会抬升水准的杠杆

下面五件事，每一件都不是补丁。只做其中一件、做彻底，比再写十份参考文档更能改变稿面。按对文字的影响排序。

### 杠杆 1：盲读门控（最大）

**改什么：** 任何进入“可交付”状态的章节或短篇，必须经过一次**看不见大纲、看不见任务卡、看不见复盘、看不见人物档案**的阅读。阅读者只拿到 `manuscript/zh/` 里这一章，以及（长篇）上一章正文。输出不是分数，是阅读经验：

- 我以为自己在读一个怎样的人
- 我在哪一段开始走神
- 我最想知道而文本没给我的是什么
- 我是否能用自己的话复述这场里发生的不可逆变化
- 哪一句听起来像作者，不像人物

只有盲读提出的问题被处理之后，才允许写 `review.md`。写作者的复盘不准先于读者。

**为什么是大规模：** 它恢复了编辑协议里被拆掉的信息不对称。现在所有“独立编辑 / 体验通读 / 伟大作品门控”都是同谋自评。

**怎样才算做成：** 盲读必须是另一次模型调用或另一个 agent，上下文里没有创作宪章。同一轮里先写后读，不算。

### 杠杆 2：本书声音锁

**改什么：** 每个项目维护一份活的、很短的声音样本，不是风格形容词。

- 从已写正文中抽出 15–40 句**本书自己的好句子**（不是金句，是有判断力的普通句子）
- 抽出 10 句**本书不准再写的句子**（本项目最容易滑进去的通用腔）
- 每章开写前，这批样本是正文生成的硬上下文，优先级高于场景计划
- 人物卡里的三句声音样本，必须作为该 POV 本章对白的约束，而不是档案装饰

冷启动应改为：宪章 + POV 声音样本 + 本书样本句 + 上一章全文或至少能覆盖上一场完整场面的篇幅。40 字一行摘要可以留着给情节，不能替代声音。

**为什么是大规模：** 中文 AI 长篇的典型死亡是“每章换一副嗓子，又都像同一副公共嗓子”。样本锁的是句法、选词、停顿，不是主题。

**怎样才算做成：** 抽盲对比第 3 章和第 23 章，遮住情节后仍能判断是同一本书。现在做不到。

### 杠杆 3：感知引擎，而不是情节引擎

**改什么：** 把“人物先于机关”从口号落成生成输入。每一场开写前，只允许从下面这种产物进入正文，不允许从“本章要揭示线索 B”进入正文：

```text
POV 此刻最想保住什么
他/她进门第一眼会看见什么（必须具体到物件或声音）
他/她会故意不看什么
他/她以为对方要什么（误判，必须写错）
他/她这轮准备用的保护策略
他/她绝不会说出口的那半句
若策略失败，身体会先做什么
```

沙盘若保留，输出合同改成上述感知包，删除“一句对白”。简单章可以缩短，但不能改成抽象的“不愿面对：真相”。

导演可以改情节；不能改“这个人不会先看见这个”。若大纲要求一个不会看价格的人进门先看价签，是大纲错了。

**为什么是大规模：** 档案里已经有“首先会注意的细节”。正文里没有。这是人物从设定变成文字的唯一缝。缝不打开，压力系统全是工作台文学。

### 杠杆 4：场景价值变化成为原子，字数降为上限

**改什么：**

- 完成条件改为：本场压力发生了不可逆变化，盲读能复述它
- 3000 / 6000 从红灯下限改为软上限或项目可选习惯，不再写入事务失败
- 允许短章。一场把关系权力翻转了，800 字就该停
- `content-expansion.md` 退出默认写作路径；需要加长时，只允许增加新的策略失败，不允许增加对已知信息的确认
- 事务验收检查“不可逆变化在正文中的位置”，不检查复盘字段是否填了字

**为什么是大规模：** 现在的美学是字数美学。不改完成条件，所有文风协议都会在注水时被绕开。

### 杠杆 5：作者模式与工厂模式分家

**改什么：** 批量、自动驾驶、跨书生产，不再与“具有独特生命”共用一条质量故事。

两条路可以共享文件格式和脚本，不能共享完成定义：

| | 作者模式 | 工厂模式 |
|---|---|---|
| 目标 | 这一本必须是这一本 | 可恢复、可并行、结构完整 |
| 冷启动 | 重读足够的正文以锁住声音 | 摘要 + 宪章，追求省上下文 |
| 沙盘 | 感知包，默认开 | 可压缩 |
| 盲读 | 硬门 | 抽检 |
| 字数 | 上限 | 可保留下限 |
| 允许说的话 | 可以停下来改大纲 | 可以停机并留下恢复点 |

现在 skill 的使命写着伟大，主路径却是工厂。模型会听主路径。把工厂说成伟大，两种东西一起坏：工厂不够快，作者不够真。

## 5. 次一级、但仍值得做的

这些改变幅度小于上一节，但对文字有用。不要用它们代替杠杆。

1. **清沉积。** 钩子映射、出版门控旧版、节奏三套、过时的 `WORKFLOW_GUIDE.md` / `OPTIMIZATION_PLAN.md`，要么归档到 `docs/legacy/`，要么改成“仅当用户明确要网文钩子课才读”。默认加载路径只留 v3 核心。
2. **修好沙盘与冷启动的互相否定。** 选一个真相：要么沙盘需要近章全文，冷启动为沙盘让路；要么沙盘只读运行时记忆和感知包，不再假装读了 1–3 章。
3. **对白参考重写。** 删掉“传递信息”作为独立合法任务。信息只能作为交易的副产品出现。
4. **卷审计改成隔卷盲读。** 每 10 章不是写一份因果表，而是让盲读通道连读 3 章，只报告“我还认不认这些人”。
5. **AI 味脚本降级为附录。** 继续跑，但修订协议禁止为了降计数而改“然而/因为”。只处理解释句、均匀句式、情绪标签。
6. **金标对照。** 仓库至少放两段不长的中文：一段是过关（有判断力的细节、对白在交易、停在余震处），一段是当前模型常交的空壳。测试可以断言空壳不该通过盲读协议——即使暂时只能用人工夹具。

## 6. 不要再加的东西

再加这些，表面更完整，文字不会更好：

- 新的评分、雷达图、健康分、伟大指数
- 新的钩子表、爽点表、节奏曲线类型
- 把 `review.md` 字段从 3 个加到 12 个
- 在同一轮里再写一份更长的“独立编辑清单”
- 用更复杂的状态机、ledger、JSON 叙事记录代替重读正文（结构化记忆救连续性，不救句子）
- 给每个题材再做一份自动填充模板
- 把字数下限再提高

Story OS 那类架构（ledger、事务、投影）解决的是**可恢复的工程问题**。它不是写作水准杠杆。 Continuity 和 quality 不是同一件事。本仓库已经用仪表盘、事务验收、批量协议把工程问题推到了足够远；继续往工程里加层，会让作者模式更难呼吸。

## 7. 若只做一件，做哪件

做**盲读门控**。

原因很具体：当前 skill 并不缺关于好小说的知识。它缺一个无法被写作者忽悠的反对者。盲读会立刻暴露：

- 因果写在工作台、没写在场面
- 人物档案与正文脱节
- 为凑字数而存在的中段
- 所有人用同一种完整中文说话

暴露之后，杠杆 2、3、4 才有打击面。没有盲读，那些改动仍会被同一轮自审涂绿。

盲读也自然逼出声音锁：读者说“这章不像上一章的人在说话”，样本句才有必要维护。它还逼出场景原子：读者说“我不知道这章改变了什么”，字数就再也无法充当完成条件。

## 8. 用什么检验这份诊断是否说对了

不要用“参考文档是否更全”检验。用稿。

取同一 premise，各写一章：

1. **现状协议：** 有界冷启动 + 任务卡 + 场景因果 + 同轮复盘 + 事务验收。
2. **杠杆协议：** 感知包进场 + 本书样本句（若无旧稿则用人物三句声音样本）+ 写完即停 + 另一次盲读后再改。

遮住工作台，只读 `manuscript/zh/`。看：

- 进门第一段是否只能由这个人写成
- 对白遮住姓名后是否还能分出人
- 是否存在一句解释是场面已经给过的
- 章末是余震还是总结
- 删掉最漂亮的一段，故事是否仍在

若两稿分不出高下，说明诊断错了，杠杆不值。若盲读稿明显更像“有人在场”，再把杠杆写进 `SKILL.md` 的主路径。在此之前，不要再扩工厂。
