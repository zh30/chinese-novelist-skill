# 写作水准优化执行方案

> 依据：[docs/2026-09-11-写作水准诊断.md](../2026-09-11-写作水准诊断.md)
> 基线：仓库 `main` v3.1.0（`3f1f9fa`）
> 性质：把诊断里的五个杠杆落成可提交的改动，而不是再写一套创作理论。

---

## 1. 目标与非目标

### 目标

让模型在**作者模式**下写出更像“有人在场”的中文：进场第一段属于这个人，对白遮名可分人，解释不重复场面，章末停在余震而不是总结。

完成定义从“字数 + 复盘字段 + 仪表盘有本章字样”改为：

1. 正文里发生了盲读能复述的不可逆变化。
2. 一次**与写作者上下文隔离**的盲读已经发生，并且盲读提出的问题被处理过。
3. 正文是从感知包和本书声音样本生成的，不是从“本章要揭示线索 B”生成的。

### 非目标

下列事项明确不做。执行时若想加，视为偏离方案：

- 新的分数、雷达图、健康分、伟大指数
- 新的钩子表、爽点表、节奏曲线类型
- 把 `review.md` 字段加长
- 同一轮里再写一份更长的独立编辑清单
- Story OS / ledger / JSON 叙事记录
- 新的题材自动填充模板
- 提高字数下限
- 用关键词表替代盲读

v3.0 的创作罗盘、人物压力系统、分层修订观念、干净正文与工作台分家，全部保留。本方案改的是**执行路径和完成条件**。

---

## 2. 执行原则

1. **先改完成条件，再改生成输入。** 不改验收，新协议会被涂绿后忽略。但第一刀仍是盲读：没有反对者，完成条件改了也没有人能说出“这场改变了什么”。
2. **盲读必须是另一次上下文。** 同一轮先写后填 `blind-read.md` 不算。写进 `SKILL.md` 的硬规则优先于任何方便。
3. **作者模式是默认主路径。** 自动驾驶 / 批量是工厂模式，共用文件格式，不共用完成定义。
4. **详细方法进 `references/`。** `SKILL.md` 继续当路由，测试仍限制其行数 ≤ 500。
5. **每阶段单独可合并。** 合入后现有单元测试必须绿；文学效果用第 9 节对照实验验，不靠口号测试代替。
6. **禁止为了降 AI 味计数而改“然而 / 因为”。** 脚本继续跑，只作线索。

---

## 3. 版本与阶段

| 版本 | 阶段 | 杠杆 | 用户可感知变化 |
|------|------|------|----------------|
| **3.2.0** | A + B | 盲读门控 + 完成条件 | 一章必须先被看不见大纲的读者读过；短章可以过关 |
| **3.3.0** | C + D | 感知引擎 + 声音锁 | 正文从“此人看见什么”和本书句子生成 |
| **3.4.0** | E + F | 模式分家 + 沉积清理 | 默认作者模式；工厂模式明示降级；旧钩子表退出默认加载 |

不要把 A–F 做成一次巨型提交。3.2 是最小有价值版本：若只合这一刀，写作水准也应可见变化。

---

## 4. 阶段总览

```text
A 盲读门控
    → B 完成条件（字数降级，不可逆变化进验收）
        → C 感知包成为生成输入（沙盘改合同）
            → D 本书声音锁 + 作者模式冷启动
                → E 作者 / 工厂分家
                    → F 沉积清理、对白重写、金标夹具
```

C 与 D 可部分并行（不同文件），但都应在 B 之后：否则感知包和声音锁写得很漂亮，事务脚本仍会因为不满 3000 字逼模型注水。

E 依赖 A–D 的作者路径已经能跑通。F 可在 E 之后，或与 E 同版本后半。

## 阶段 A — 盲读门控（v3.2 上半）

### 目标

任何进入可交付状态的章节 / 短篇，必须经过一次只看见正文的阅读。写作者的 `review.md` 不准先于读者。

### 成功标准

- [ ] 存在 `references/blind-read.md`，规定隔离输入、禁止打开的文件、输出格式、失败时如何改稿。
- [ ] 工作台多了 `blind-read.md`；`review.md` 必须引用盲读中的走神点 / 不可复述点，并记录改了什么。
- [ ] `SKILL.md` 连载循环改为：写正文 → **派出盲读** → 按盲读改稿 → 再写复盘。删除“同一上下文做独立编辑并勇敢一刀”作为完成步骤。
- [ ] 事务脚本检查 `blind-read.md` 必填区块非空；缺文件则失败。
- [ ] 文档测试断言：`SKILL.md` 含“盲读”、禁止同上下文填写盲读、链接 `references/blind-read.md`。
- [ ] 夹具测试：无 `blind-read.md` 的章节事务失败；有完整盲读 + 旧复盘字段则通过（本阶段暂保留字数下限，以免和 B 耦合）。

### 盲读协议（写入 `references/blind-read.md`，此处锁定口径）

**派出方式（硬）：** 使用 subagent 或新的隔离调用。该次调用的可读文件白名单：

- 长篇：`manuscript/zh/` 本章全文；若非第 1 章，加上上一章全文。
- 短篇：该短篇文件中的正文区。

禁止打开：`00-大纲.md`、`01-人物档案.md`、`99-进度仪表盘.md`、`workspace/`、`04-角色沙盘/`、`02-世界观与伏笔.md`、任何任务卡 / 场景计划 / 复盘。

若当前宿主无法派出隔离 agent：停止交付，向用户说明，并给出“请另开一次只读这两份正文的对话”的恢复指令。**不准**在写作上下文里假装盲读。

**盲读输出**（`workspace/chapters/第XXX章-标题/blind-read.md`）：

```markdown
# 盲读

- **我以为自己在读一个怎样的人**：
- **走神起点**：（引用原文短句；没有则写“无”）
- **我最想知道而文本没给的**：
- **不可逆变化（读者复述）**：复述不出则写“复述不出”
- **听起来像作者、不像人物的句子**：（引用；没有则写“无”）
- **是否还想翻下一页**：想 / 勉强 / 不想
- **一句话总判**：
```

禁止打分。禁止根据题材模板猜测作者意图。复述不出不可逆变化 = 盲读失败，写作者必须改正文后重新派出盲读，不得只改复盘措辞。

**写作者在盲读之后：**

1. 只处理盲读提出的最高杠杆问题（走神、复述不出、作者腔）。
2. 再写 `review.md`，其中必须有「盲读指出 / 正文改动」两行。
3. 不得把盲读失败写成“读者理解有误”。

|------|------|
| 新建 | `references/blind-read.md` |
| 修改 | `references/chapter-workspace-template.md`（加入 `blind-read.md`，复盘增加盲读引用） |
| 修改 | `references/editorial-revision.md`（第 0 轮体验通读改为盲读协议；同上下文边注降为可选草稿，不能代替盲读） |

| 修改 | `scripts/check_chapter_transaction.py`（检查盲读文件与必填标签） |

| 修改 | `tests/test_skill_docs.py` |
| 修改 | `FILE_INDEX.md`、`README.md`、`CHANGELOG.md` |

### 任务顺序

1. 先写失败测试：完整旧事务（有复盘无盲读）必须失败。
2. 实现脚本检查与模板。
3. 改 `SKILL.md` 循环，保持 ≤ 500 行：盲读细节只指向 reference。
4. 更新 FILE_INDEX / README / CHANGELOG（版本仍可先写 unreleased，等与 B 一并标 3.2.0）。

### 风险

- 宿主没有可靠 subagent：必须失败可见，不能静默降级。
- 模型把盲读写成夸奖：协议要求引用原文短句；“无走神 / 无作者腔”允许，但“复述不出”必须卡住交付。
- 与现有“独立编辑”并列会造成双轨。本阶段删掉同轮独立编辑作为必做步，避免回潮。

## 阶段 B — 完成条件：价值变化为原子，字数降为上限（v3.2 下半）

### 目标

作者模式下，字数不再能单独否决一章。事务失败的文学理由只有：正文不存在、盲读缺失或复述不出、仪表盘未回写。

### 成功标准

- [ ] `check_chapter_transaction.py` 作者模式默认**不**因低于 3000 失败。字数仍打印。可设软上限警告（建议 8000，不失败）。
- [ ] 增加检查：`blind-read.md` 的「不可逆变化（读者复述）」不是占位符，也不是“复述不出”。
- [ ] `check_chapter_wordcount.py` 默认改为报告模式：低于旧习惯值时打印建议，退出码 0；`--strict-min N` 才失败（供工厂模式调用）。
- [ ] 短故事：6000 从红灯失败改为建议值；结构闭合与盲读复述仍是硬项。`check_short_story.py` 同步。
- [ ] `SKILL.md` 删除“标准长篇不少于 3000 / 快速 2500 / 短篇不少于 6000”作为必须过关条件；改为“写到压力变化完成即停；习惯篇幅见项目设定，不是验收失败项”。
- [ ] `content-expansion.md` 退出默认写作路径：`SKILL.md` 和 FILE_INDEX 不再在“字数不足”时指向它。需要加长时只允许增加新的策略失败。
- [ ] 质量清单与事务脚本口径一致：字数是边界报告，不是质量代理。

### 文件

| 动作 | 路径 |
|------|------|
| 修改 | `scripts/check_chapter_transaction.py` |
| 修改 | `scripts/check_chapter_wordcount.py` |
| 修改 | `scripts/check_short_story.py` |
| 修改 | `tests/test_check_chapter_transaction.py` |
| 修改 | `tests/test_check_chapter_wordcount.py` |
| 修改 | `tests/test_check_short_story.py` |
| 修改 | `SKILL.md`、`references/quality-checklist.md`、`references/short-story-template.md` |
| 修改 | `FILE_INDEX.md`、`README.md`、`QUICK_START.md`、`CHANGELOG.md` |

工厂模式的字数下限留到阶段 E 再打开。本阶段全局先按作者模式改，避免 3.2 仍在用字数逼注水。若必须兼容旧用户“我要每章 3000 字”，允许项目仪表盘写 `篇幅习惯：3000` 作为**软提示**，脚本不失败。

### 任务顺序

1. 改事务脚本：字数检查改为 `word_count_report`（passed 恒真，message 带数字）；新增 `irreversible_change` 检查盲读复述。
2. 字数脚本与短篇脚本退出码策略。
3. 改 SKILL / 清单 / 短篇模板用词。
4. 从默认路径拿掉 `content-expansion.md`。
5. 标版本 3.2.0，CHANGELOG 写明：盲读成为硬门，字数不再否决作者模式章节。

### 风险

- 旧项目 / 旧测试假定 3000 失败。全部改测试，并在 CHANGELOG 写破坏性变更。
- 模型会把“复述不出”改成一句空的“关系变了”。标签提取后可加弱启发式：复述长度过短或仅含“变化 / 推进 / 升级”则失败。不要做文学打分器。

## 阶段 C — 感知引擎（v3.3 上半）

### 目标

正文只允许从感知包进入，不允许从“本章要揭示线索 B”进入。沙盘输出合同与冷启动停止互相否定。

### 成功标准

- [ ] 工作台新增 `perception.md`，字段与诊断杠杆 3 一致，全部要求具体到物件、声音、错的判断、半句话，禁止抽象名词充数。
- [ ] `SKILL.md` 连载顺序：冷启动 → **感知包** →（可选）场景因果 → 写正文。任务卡仍可写存在理由，但不能替代感知包。
- [ ] 沙盘：删除“一句可能说出口的话”；深度发言的产物就是感知包。简单章也必须有缩短版感知包，不能跳过。
- [ ] 沙盘参考不再要求导演默认重读最近 1–3 章全文；改为读运行时记忆 + 本章感知所需的有限信息。与作者模式冷启动一致。
- [ ] 单角色运行时文件删除信任度 / 依赖度 / 冲突度百分比和压力 `__/10`，改回可观察证据（与人物模板 v3 对齐）。
- [ ] 导演可以改情节，不能改“这个人不会先看见这个”。写入沙盘裁决优先级，置于“原大纲章节安排”之上、与人物一致性并列。

### `perception.md` 口径

```markdown
# 感知包

- **POV**：
- **此刻最想保住的**：
- **进门第一眼**：（物件或声音，必须可被拍摄）
- **故意不看的**：
- **以为对方要什么**：（必须是误判，写错的那种）
- **本轮保护策略**：
- **绝不会说出口的半句**：
- **策略失败时身体先做的**：
```

缩短版（快速模式）至少保留：第一眼、误判、不肯说的半句。

事务脚本**不**把感知包做成新的文学分数；3.3 可检查文件存在且非占位符，防止又被跳过。占位符规则复用现有 `is_placeholder`。

| 动作 | 路径 |
|------|------|
| 修改 | `references/chapter-workspace-template.md` |
| 修改 | `references/14-角色沙盘模式.md` |
| 修改 | `SKILL.md`（步骤 2–4） |
| 修改 | `references/character-template-v2.md`（章节调用卡指向感知包） |
| 修改 | `scripts/check_chapter_transaction.py`、对应测试 |
| 修改 | `FILE_INDEX.md`、`CHANGELOG.md` |

### 任务顺序

1. 模板与沙盘参考一次改完，避免两套输出合同并存。
2. SKILL 循环插入感知包，并写明：场景计划是可选的因果备忘，正文以感知包为准。
3. 事务检查 `perception.md`。
4. 更新角色沙盘索引 / README 中“每章一句对白”的过时描述。

### 风险

- 感知包被填成“真相 / 爱情 / 尊严”。检查可要求第一眼字段不含这些词作为唯一内容，并要求至少有一个具体名词（可做极弱启发式，不要扩大成语义模型）。
- 与任务卡重复。任务卡保留“存在理由 / 不可逆变化 / 代价”；感知包只负责进场意识。不要把任务卡扩成第二份感知包。

## 阶段 D — 本书声音锁与作者模式冷启动（v3.3 下半）

### 目标

每本书有一份很短的活样本。开写时样本的优先级高于场景计划。冷启动停止用 40 字摘要 + 800 字尾巴代替文风。

### 成功标准

- [ ] 小说根目录新增 `05-声音锁.md`（或 `workspace/voice-lock.md`，二选一，推荐根目录与大纲同级，冷启动一眼能找到）。
- [ ] 模板含：15–40 句本书好句子（判断力普通句，不是金句）；最多 10 句禁止再写的句子；POV 声音样本三句的指针（指向人物档案，不复制两份权威）。
- [ ] 作者模式冷启动必读：创作宪章 + `05-声音锁.md` + 本章 POV 档案中的声音样本与“首先会注意的细节” + **上一章全文**（第 1 章无此条）。仪表盘 40 字一行只作情节索引，不再是文风来源。
- [ ] 删除作者模式“禁止默认重读最近 1–3 章全文”。改为：默认重读上一章全文；需要改稿或审计时再扩大。
- [ ] 盲读提出“不像上一章的人在说话”或“像作者腔”时，把问题句追加进禁止列表，把改后的好句追加进样本（有上限，先进先出，避免文件膨胀）。
- [ ] 首章无旧稿时：用人物三句声音样本 + 风格宪章启动，写完并盲读通过后立即抽第一批样本。

### 文件

| 动作 | 路径 |
|------|------|
| 新建 | `references/voice-lock-template.md` |
| 修改 | `SKILL.md`（冷启动段、策划期创建最小文件） |
| 修改 | `references/outline-template-v1-minimal.md` 或策划说明（创建 `05-声音锁.md`） |
| 修改 | `references/progress-dashboard-template.md`（冷启动说明改口） |
| 修改 | `references/style-polishing.md`（风格宪章与声音锁的关系：宪章是选择，锁是例句） |
| 修改 | `references/blind-read.md`（盲读后回写声音锁） |
| 修改 | `FILE_INDEX.md`、`CHANGELOG.md`、`tests/test_skill_docs.py` |

本阶段**不要**写抽句子脚本。抽句是写作 agent 在盲读通过后的判断，不是 n-gram。脚本化抽“好句子”会把平庸句锁死。

### 任务顺序

1. 模板 + 策划期创建文件。
2. 改冷启动，删除 800 字禁令。
3. 盲读协议增加回写声音锁的一步。
4. 标版本 3.3.0。

### 风险

- 上一章全文会增加 token。这是作者模式付的钱，阶段 E 的工厂模式才允许回到摘要。不要在 D 里偷偷加回 800 字。
- 声音锁写成风格形容词（“冷峻、细腻”）。模板示例必须是完整句子。

## 阶段 E — 作者模式与工厂模式分家（v3.4 上半）

### 目标

使命不再和批量共用完成定义。默认“写一本 / 继续写”走作者模式。只有明确的自动驾驶 / 批量走工厂模式。

### 成功标准

- [ ] `SKILL.md` 意图路由出现两列完成定义，或单独一小节「写作模式」。
- [ ] 仪表盘字段 `写作模式：作者 / 工厂`。新项目默认作者。用户说“自动写完整本 / 批量写 / 快写”才切工厂。
- [ ] 对照表落地（与诊断一致）：

| | 作者 | 工厂 |
|---|---|---|
| 冷启动 | 声音锁 + 上一章全文 | 摘要 + 宪章 + 末尾 800 字 |
| 感知包 | 默认完整 | 可缩短 |

| 字数 | 报告 + 软上限 | 可启用 `min_words`（长篇 3000 / 快写 2500 / 短篇 6000） |
| 失败 | 盲读复述不出则改稿 | 事务失败重试，连续 2 次停机留恢复点 |
| 允许 | 停下来改大纲 | 不停主线，只留恢复点 |

- [ ] `check_chapter_transaction.py` 读仪表盘模式：作者走 A+B 规则；工厂可 `--factory` 或自动检测后恢复字数下限，盲读改为 optional + `抽检标记`。

## 9. 文学验收（诊断第 8 节，3.2 后做一次，3.3 后再做一次）

不要用“参考文档是否更全”宣布成功。用稿。

同一 premise，各写一章：

1. **基线：** v3.1 协议（有界冷启动 + 任务卡 + 场景因果 + 同轮复盘 + 事务验收）。可在合入前用当前 main 打一份样稿，存 `docs/samples/v31-baseline.md`（不进 skill 默认加载）。
2. **3.2 稿：** 感知包尚未强制，但必须隔离盲读，写到变化完成为止。
3. **3.3 稿：** 感知包 + 声音锁（首章用人物三句样本）。

遮住工作台，只读 `manuscript/zh/`，问：

- 进门第一段是否只能由这个人写成
- 对白遮名是否可分人
- 是否存在场面已经给过、后面又解释一遍的句子
- 章末是余震还是总结
- 删掉最漂亮一段，故事是否还在

记录结论到 `docs/samples/quality-trial-notes.md`。若 3.2 与基线分不出高下，停下来修盲读协议，不要继续堆 C–F。若 3.2 已明显更像有人在场，再开 3.3。
