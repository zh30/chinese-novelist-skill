# 角色沙盘模式

> 在人物逻辑最需要独立推演时，让人物先活一次，再让作者写。

角色沙盘模式让关键人物以自己的有限认知提出行动倾向，导演再根据人物一致性、因果、主线和代价做最终裁决。它是高价值工具，不是每章必须生成的仪式；简单章节使用任务卡中的人物压力检查即可。

## 适用场景

- 多人物冲突、群像、权谋、悬疑、言情拉扯、反派行动章
- 角色动机不清、人物像工具人、关系变化太硬的章节
- 人物自然选择与原大纲明显冲突的章节
- 自动驾驶写作中防止人物后期漂移

快速模式或简单章节可以只做 POV 角色的目标 / 策略 / 误判 / 边界检查，不创建完整沙盘记录。

## 核心原则

### 先过人物意志，不强制过形式

章节不能直接由大纲机械生成。每章都要验证人物目标、策略和信息边界；只有复杂或可疑章节才展开完整沙盘。

### 角色可以反抗大纲

角色可以提出与原大纲不同的自然行动。导演必须裁决，不可忽略。

裁决优先级：

1. 人物一致性
2. 主线不可断
3. 既有因果与已支付代价
4. 原大纲章节安排
5. 单章预期效果

### 有限信息

角色 subagent 只能看到角色在小说内应当知道的信息，不能看到完整大纲、未来剧情、其他角色内心、隐藏真相或作者意图。

### 角色不写正文

角色 subagent 只输出行动倾向、场景建议和一句可能说出口的话。正文由写作 agent 根据导演裁决后的任务卡完成。

## 文件结构

在小说目录中新增：

```text
04-角色沙盘/
├── 00-角色索引.md
├── C001-角色名.md
├── C002-角色名.md
└── sessions/
    ├── 第001章-沙盘记录.md
    ├── 第002章-沙盘记录.md
    └── ...
```

文件分工：

| 文件 | 作用 |
|------|------|
| `01-人物档案.md` | 静态设定：人物是谁、欲望、恐惧、声音、缺陷、人物弧线 |
| `04-角色沙盘/00-角色索引.md` | 调度表：哪些角色核心、活跃、潜伏或冻结 |
| `04-角色沙盘/C001-角色名.md` | 单角色运行时记忆：当前目标、已知事实、误判、关系判断 |
| `04-角色沙盘/sessions/第XXX章-沙盘记录.md` | 每章沙盘会议记录和导演裁决 |
| `99-进度仪表盘.md` | 只保留沙盘摘要和恢复入口 |

## 角色等级

| 等级 | 含义 | 每章处理 |
|------|------|----------|
| 核心 | 主角、反派、关键关系人物 | 每章心跳，出场章深度发言 |
| 活跃 | 近期推动剧情的人物 | 相关章节发言，其他章节可心跳 |
| 潜伏 | 暗线人物、未来关键人物 | 被悬念/关系/任务触发时唤醒 |
| 冻结 | 暂无作用人物 | 状态不更新 |

## 角色索引模板

```markdown
# 角色沙盘索引

| ID | 角色 | 文件 | 等级 | 当前状态 | 最近出场 | 本章处理 |
|---|---|---|---|---|---|---|
| C001 | 林墨 | C001-林墨.md | 核心 | 高压追查 | 第12章 | 深度发言 |
| C002 | 苏晴 | C002-苏晴.md | 核心 | 隐瞒真相 | 第12章 | 深度发言 |
| C003 | 老马 | C003-老马.md | 活跃 | 观察主角 | 第11章 | 轻量心跳 |
```

```markdown
- 当前目标：

- 可用资源：
- 当前弱点：

|---|---|---|---|

## 关系判断
| 对象 | 信任度 | 依赖度 | 冲突度 | 角色自己的判断 |
|---|---:|---:|---:|---|

| 隐瞒内容 | 对谁隐瞒 | 原因 | 暴露后果 |
|---|---|---|---|

| 章节 | 原大纲期望 | 角色自然倾向 | 裁决 | 后果 |

- 我现在最想要：
- 我最担心：
- 我可能会主动做：

```

维护规则：

- 单角色文件建议保持在 1500-3000 字。
- 超过长度时，把旧行动历史压缩为阶段摘要。
- 不要把整章复述进角色文件，只回写状态变化。

## 每章执行流程

### 1. 读取状态

导演读取：

- `99-进度仪表盘.md`
- `00-大纲.md`
- `01-人物档案.md`
- `04-角色沙盘/00-角色索引.md`
- 最近 1-3 章
- 悬念追踪表和世界观文件，如存在

### 2. 选角

导演决定本章处理方式：

| 处理方式 | 适用对象 |
|----------|----------|
| 深度发言 | 本章出场人物、POV 人物、冲突核心人物、掌握关键隐瞒的人物 |
| 轻量心跳 | 核心人物但本章不出场，或本章事件会影响的人物 |
| 冻结 | 暂时无关配角、工具人 |

默认每章深度发言角色 1-4 个。群像高潮可增加，但要避免所有角色都长篇发言。

### 3. 分发有限信息

给角色 subagent：

- 自己的运行时文件
- 最近一次相关章节摘要
- 自己已知事实
- 自己的误判，不给实际真相
- 当前外部局势中该角色能观察或合理得知的部分
- 与自己有关的关系状态

不给角色 subagent：

- 完整大纲
- 结局和未来章节安排
- 其他角色内心
- 作者隐藏设定
- 该角色尚不知道的真相

### 4. 角色深度发言

```markdown
# 角色沙盘输出：[角色名]

## 1. 行动倾向
我本章最可能主动做：___
原因：___
我希望达成：___
我愿意付出的代价：___

## 2. 反抗大纲
原大纲可能要求我：___
但以我的当前状态，我更可能：___
冲突等级：低 / 中 / 高

## 3. 信息与误判
我现在知道：___
我误以为：___

## 4. 关系判断
我对 A 的判断：___
我对 B 的判断：___
我会信任 / 试探 / 隐瞒 / 攻击谁：___

## 5. 场景建议
如果本章有我的戏，我最自然出现的场景是：___
这个场景里的冲突应该是：___

## 6. 一句可能说出口的话
> “___”
```

### 5. 轻量心跳

```markdown
| 角色 | 是否受本章影响 | 状态变化 | 下章风险 |
|---|---|---|---|
| 苏晴 | 是 | 压力上升，继续隐瞒 | 如果林墨追问，关系裂痕扩大 |
```

### 6. 导演裁决

```markdown
# 第 X 章角色沙盘裁决

## 参与角色
| 角色 | 处理方式 | 原因 |
|---|---|---|

## 角色冲突矩阵
| 冲突双方 | 冲突点 | 谁主动 | 谁误判 | 戏剧价值 |
|---|---|---|---|---|

## 大纲反抗裁决
| 角色 | 原大纲期望 | 自然倾向 | 冲突等级 | 裁决 |
|---|---|---|---|---|

## 本章任务卡修订
- 大纲目标：
- 角色自然行动：
- 导演裁决：
- 本章不可逆变化：
- 必须推进的悬念：
- 结尾钩子：

## 回写要求
- 更新哪些角色文件：
- 更新哪些关系：
- 哪些误判加深 / 修正：
- 哪些信息进入已知事实：
```

裁决类型：

| 裁决 | 用法 |
|------|------|
| 吸收 | 修改本章任务卡，让剧情顺着角色自然行动走 |
| 驳回 | 保持原大纲，但正文中必须给出角色被迫照做的小说内原因 |
| 延后 | 角色想这么做，但本章被阻止，转化为后续悬念 |
| 分叉记录 | 保留为备用支线或重写候选，不进入当前正文 |

## 写作规则

- 正文只能根据导演裁决后的任务卡写。
- 角色给出的一句对白可以作为素材，但写作时可以重写。
- 角色给出的场景建议必须经过导演整合，不可直接照搬。
- 如果导演驳回角色倾向，正文中要出现压力、阻碍或代价，让角色被迫进入剧情。

## 回写规则

每章完成后更新：

- `99-进度仪表盘.md` 的沙盘摘要
- `04-角色沙盘/00-角色索引.md`
- 本章涉及的单角色运行时文件
- `04-角色沙盘/sessions/第XXX章-沙盘记录.md`

每个角色至少回写：

- 新知道了什么
- 误判是否加深、修正或转移
- 当前压力变化
- 关系判断变化
- 隐瞒事项是否暴露
- 下一步倾向

## 快速模式

快速模式仍执行角色沙盘，但压缩为：

1. POV 或主角深度发言
2. 其他核心人物轻量心跳
3. 导演一句裁决
4. 直接生成正文

快速模式不生成完整冲突矩阵，但必须保留“反抗大纲检查”。

## 自动驾驶模式

自动驾驶模式每章也执行沙盘。若上下文或时间不足，可以降级为主模型内部模拟，但必须在沙盘记录中标注：

```markdown
本章沙盘执行方式：降级模拟
原因：上下文/时间不足
深度发言角色：___
轻量心跳角色：___
```

自动驾驶连续 3 章出现高冲突反抗大纲时，应暂停并输出诊断，防止剧情漂移。

## 越权处理

如果角色 subagent 输出了不该知道的内容：

```markdown
## 越权记录
- 角色：
- 越权内容：
- 处理方式：忽略 / 转为角色误判 / 交由导演判断
```

如果角色创造新设定或隐藏真相，默认忽略，除非导演明确吸收并同步更新大纲和世界观。

## 交付检查

每章写作前：

- [ ] 已读取角色索引
- [ ] 已选择深度发言、轻量心跳、冻结角色
- [ ] 角色只收到有限信息
- [ ] 至少 POV / 主角完成深度发言
- [ ] 已处理所有反抗大纲点
- [ ] 已生成导演裁决

每章写作后：

- [ ] 已写入沙盘记录
- [ ] 已更新相关角色运行时文件
- [ ] 已更新角色索引
- [ ] 已更新仪表盘沙盘摘要
- [ ] 角色文件没有无限膨胀

## 与其他机制的关系

- 与悬念生命周期：沙盘决定谁知道、误会、隐瞒和推进悬念。
- 与多线叙事：不同线的核心角色用轻量心跳保温。
- 与 AI 味检查：角色的“声音指纹”和一句对白用于减少统一作者腔。
- 与修改工作流：修改章节时必须检查角色沙盘记录，避免改动破坏后续角色状态。
