# 批量生产协议

> 用于一次推进多本长篇或多篇短故事。质量标准与单书相同；批量只扩大持续性，不降低验收。

## 何时进入

用户明确说“批量写”“自动写多本”“一次写几本”“批量短篇”，或一次给出多个可独立成书的 premise。不要把“自动写完整本”理解成批量：那仍是单书自动驾驶。

## 任务清单

创建或更新 `novels/00-批量任务清单.md`：

```markdown
# 批量任务清单

> 一实例一次只认领一本书。状态以本文件和各书仪表盘为准。

## 条目

### B001 [书名]
- **类型**：长篇 / 短篇
- **premise**：
- **目标规模**：20 章 / 6000 字
- **状态**：策划 / 连载中第 N 章 / 收尾 / 完成 / 失败
- **失败原因**：无 / ___
- **恢复点**：无 / 第 N 章事务未通过
- **认领者**：空闲 / 本实例
- **宪章差异**：
  - 题材：
  - 主角策略：
  - 结局代价：
- **路径**：`novels/书名/` 或 `short-stories/YYYYMMDD-标题.md`

## 差异登记

新书立项前，用一句话说明它与清单中已有条目在题材、主角策略、结局代价上的不同。不能只换书名、职业或金手指名称。
```

状态只允许上表中的值。`连载中第 N 章` 表示第 N 章事务已通过，下一事务写第 N+1 章。

## 原子事务

一次推进只完成下列之一，然后停下来回写清单：

| 类型 | 完成定义 |
|------|----------|
| 长篇策划 | 方向已选，`00-大纲.md`、`01-人物档案.md`、`99-进度仪表盘.md`、首章任务卡已落盘 |
| 长篇章 | 正文 + 工作台 + 仪表盘滚动摘要 + `check_chapter_transaction.py` 通过 |
| 短篇 | 命名 Markdown 文件含任务卡、骨架、正文、复盘，且 `check_short_story.py` 通过 |
| 卷末审计 | `workspace/audits/卷X-审计.md` 已写，并已跑时间线、人物、健康检查 |
| 完本 | 收尾轮已做，清单状态改为完成；同批有多书时再跑跨书检测 |

禁止在一次事务里写完多章后才验收。会话内连写可以连续执行多个事务，但每个事务必须单独落盘和验收。

## 冷启动与认领

1. 读取 `novels/00-批量任务清单.md`。
2. 认领第一个状态不是“完成 / 失败”且认领者为空闲的条目；并行时一实例一本书，写入认领者后立刻保存。
3. 长篇只读该书仪表盘滚动前情摘要、大纲宪章区、POV 人物卡、上一章末尾 800 字。
4. 短篇只读该条目 premise、宪章差异和目标路径是否已存在。
5. 执行一个原子事务。
6. 回写清单状态；若本书已完成或失败，释放认领者。

## 失败与重试

- 验收失败：补写缺失产物，立刻重试同一事务一次。
- 连续 2 次失败：将该条目标为失败，写下恢复点和原因，停止本书。
- 文件写入失败、上下文无法恢复或用户打断：同样写恢复点后停机。
- 恢复时从恢复点重做该事务，不重写已通过的章节。

## 跨书差异

策划新书时必须填写宪章差异，并与清单中已有条目比较。完本或整批结束时运行：

```bash
python3 scripts/check_cross_book_similarity.py novels
```

报告只是烟雾报警器：4-gram 重合、意象词重合、开篇结尾句式相近、人名撞车。命中后回到正文判断，不按关键词批量改写。

## 外部循环

同一协议可用于会话内连写、外部 CLI 循环或多实例并行。外部循环每次调用只要求完成一个原子事务：

```text
读取 SKILL.md 与 references/batch-production.md。
认领 novels/00-批量任务清单.md 中的下一个未完成条目。
只完成一个原子事务，运行对应验收脚本，回写清单后结束。
不要在对话中粘贴正文。
```

Codex 示例：`codex exec "<上面那段>"`

Claude Code 示例：`claude -p "<上面那段>"`

无 skill 机制的 Agent：先把仓库放到工作区，再用同一段提示词，并要求先读 `SKILL.md`。
